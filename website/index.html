Open-source prompt infrastructure

Version-control your AI prompts like application code.

PromptOpsKit turns prompts into plain Markdown files that live in your repo. Model settings, sampling parameters, environment overrides, variable placeholders, and shared instructions are all defined in one file — then rendered into ready-to-send request bodies for OpenAI, Anthropic, Gemini, or OpenRouter.

Install from npm Quick start 
npm install promptopskit

The problem: prompts are invisible infrastructure

Most teams embed prompts as string literals scattered across application code. Model parameters live in config files. Environment differences are handled with if/else branches. When a prompt changes, there is no diff to review, no schema to validate, and no way to share instructions across features without copy-pasting.

Prompts buried in code

String constants and template literals are hard to diff, review, or audit. Prompt changes hide inside application commits with no clear ownership.

Settings scattered everywhere

Model names, temperature, reasoning effort, and max tokens live in separate config objects — disconnected from the prompt they belong to.

Duplication across environments

Dev uses a cheaper model. Prod uses a different one. Free-tier caps output tokens. Each variation means another copy of the same prompt.

The solution: prompts as versioned, composable Markdown files

PromptOpsKit gives every prompt a single Markdown file that captures everything — model settings, sampling parameters, environment overrides, variable declarations, and composable includes — so prompts are diffable, reviewable, and portable.

Version-controlled prompts

Each prompt is a .md file with YAML front matter. It diffs in pull requests, merges through your normal workflow, and has a clear history in git.

Model & parameter settings in one place

Model name, temperature, top_p, reasoning effort, max output tokens, and response format are declared in front matter — right next to the prompt text they govern.

Environment & tier overrides

Define environments and tiers in front matter to swap models and parameters for dev/prod or free/pro without duplicating the prompt file.

Data insertion with variables

{{ variable }} placeholders inject runtime data into prompts. Declared inputs are validated before rendering — missing or extra variables are caught early.

Composable shared instructions

includes lets you define tone, policy, or safety instructions once and prepend them to any prompt. No copy-paste, no drift, with circular dependency detection.

Provider-portable output

Render the same prompt for OpenAI, Anthropic, Gemini, or OpenRouter. Each adapter produces the correct request body shape — you own the HTTP call.

How it works

1. Install and scaffold

npm install promptopskit
npx promptopskit init ./prompts

Creates a prompts/ directory with starter files and a shared instructions folder.

2. Write a prompt file

One Markdown file defines everything: model, parameters, overrides, variables, includes, and prompt text.

---
id: support.reply
schema_version: 1
provider: openai
model: gpt-5.4
reasoning:
  effort: medium
sampling:
  temperature: 0.7
context:
  inputs:
    - user_message
    - app_context
includes:
  - ./shared/tone.md
environments:
  dev:
    model: gpt-5.4-mini
    sampling:
      temperature: 0.2
  prod:
    model: gpt-5.4
tiers:
  free:
    model: gpt-5.4-mini
  pro:
    model: gpt-5.4
---

# System instructions

You are a helpful support assistant working in {{ app_context }}.

# Prompt template

{{ user_message }}

3. Render for any provider

Load the prompt, supply variables, and get a ready-to-send request body.

import { createPromptOpsKit } from 'promptopskit';

const kit = createPromptOpsKit({ sourceDir: './prompts' });

const { request } = await kit.renderPrompt({
  path: 'support/reply',
  provider: 'openai',
  environment: 'prod',
  tier: 'pro',
  variables: {
    user_message: 'How do I reset my password?',
    app_context: 'Account settings page',
  },
});

// request.body is shaped for OpenAI — send it with your own HTTP client
const res = await fetch('https://api.openai.com/v1/chat/completions', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    Authorization: `Bearer ${process.env.OPENAI_API_KEY}`,
  },
  body: JSON.stringify(request.body),
});

Features for engineering teams

Validation & schema checks

  • Zod schema validation for front matter
  • Levenshtein-based "did you mean?" for field typos
  • Variable usage checks — missing and unused inputs
  • Strict mode fails on any unresolved placeholder

CLI for local dev and CI

  • init — scaffold starter prompts
  • validate — check all prompts before merge
  • compile — pre-compile .md → JSON or ESM
  • render — preview output with test variables
  • inspect — print normalized prompt as JSON
  • skill — deploy AI agent instructions

Compiled artifacts for production

  • Pre-compile prompts to JSON or ESM — skip parsing at runtime
  • Auto mode loads compiled when available, falls back to source
  • LRU cache with mtime-based invalidation during development

No transport lock-in

  • Adapters return request body only — no HTTP client bundled
  • You control auth, retries, headers, and observability
  • Works with any fetch wrapper, SDK, or infrastructure

Frequently asked questions

Is PromptOpsKit only for one model provider?

No. It ships with adapters for OpenAI, Anthropic, Gemini, and OpenRouter. Each produces the correct request body shape for that API.

Does it make HTTP requests for me?

No. PromptOpsKit returns request-body payloads. Your application owns transport, auth, retries, and headers.

Can I validate prompts in CI?

Yes. Run promptopskit validate ./prompts --strict in your pipeline to catch schema errors, missing variables, and broken includes before deploy.

How do overrides work?

Define environments and tiers in front matter. At render time, pass environment and tier to apply the right model and parameter set. Precedence: base → env → tier → runtime.

What does composability look like?

Add an includes array in front matter pointing to other .md files. Their system instructions are prepended to the current prompt. Circular includes are detected automatically.

Is PromptOpsKit open source?

Yes. MIT-licensed, maintained on GitHub, and designed so you never depend on a hosted service.
